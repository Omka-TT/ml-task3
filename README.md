# Пайплайн предобработки данных без утечки (Titanic)

Учебный проект: сборка пайплайна предобработки на scikit-learn с разными стратегиями для числовых и категориальных признаков и проверкой отсутствия data leakage.

**Датасет:** [Titanic — Machine Learning from Disaster](https://www.kaggle.com/competitions/titanic) (`train.csv`, 891 строка).

## Структура проекта

├── data/train.csv # исходные данные
├── notebooks/pipeline.ipynb # решение
├── requirements.txt
└── README.md


## Классификация признаков и стратегии

| Признак | Тип | Пропуски | Стратегия |
|---|---|---|---|
| Age | числовой непрерывный | 177 (19.9%) | медиана + StandardScaler |
| Fare | числовой, скошенный | нет | медиана (страховка) + StandardScaler |
| SibSp, Parch | числовой дискретный | нет | медиана (страховка) + StandardScaler |
| Sex | категориальный бинарный | нет | "unknown" (страховка) + OneHot |
| Pclass | порядковый, трактуется как категория | нет | "unknown" (страховка) + OneHot |
| Embarked | категориальный | 2 (0.2%) | "unknown" + OneHot |
| Cabin | категориальный, 147 уникальных | 687 (77.1%) | удалён |
| PassengerId, Name, Ticket | идентификаторы / текст | нет | удалены |

## Обоснование заполнения пропусков

- **Age — медиана:** распределение скошено, есть выбросы, среднее смещается, медиана устойчива.
- **Fare, SibSp, Parch — медиана:** скошенное распределение / дискретные счётчики; пропусков в train нет, импутер — страховка.
- **Embarked — отдельная категория "unknown":** значение нельзя угадать; мода выдумала бы данные, а 0 смешал бы пропуск с реальным значением.
- **Cabin — удалён:** 77% пропусков и 147 уникальных значений, one-hot раздул бы размерность.

Общее правило: среднее — для симметричных данных, медиана — для скошенных и с выбросами, отдельная категория — для категориальных, когда пропуск информативен или значение неизвестно.

## Как избежана утечка данных

1. `train_test_split` (712 / 179, `stratify`, `random_state=42`) выполнен до любых вычислений статистик.
2. Все шаги объединены в `ColumnTransformer` + `Pipeline`.
3. `fit_transform` вызван только на train, на test применён только `transform`.
4. Проверки в ноутбуке:
   - число столбцов train и test совпадает: (712, 13) и (179, 13);
   - после обработки NaN нет;
   - медианы импутера равны медианам train и отличаются от медиан test;
   - среднее после масштабирования на train = 0, на test ≠ 0.
5. Для сравнения показан неправильный подход (scaler на всех данных) и объяснено, почему он ведёт к утечке.

## Результат

`Pipeline` (предобработка + `LogisticRegression`), обученный на train: accuracy на test = **0.804**.
